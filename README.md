# DevHub 前端

Vue 3 + Vite，包含账号管理、本地开发工具及小游戏。

## 登录和小游戏

顶部提供注册、登录及退出登录。登录仅用于游戏积分，账号管理保持原有访问方式。
通过「小游戏 → 贪吃蛇」或 `/#/games/snake` 进入游戏：最多 8 颗果实、每颗 20 分、边界穿越、填满棋盘获胜。
方向键 / WASD 控制转向，空格暂停和继续；触屏可用方向按钮。切换页面或打开登录窗口会暂停。

游客可直接试玩；登录后新开的对局由后端生成，结束、重新开始或点击「结束并记分」时提交移动记录，由后端复算并保存。
成绩保存失败时可重试，不重复记分；也可选择放弃该局成绩。登录身份变化会重置当前对局，刷新页面会丢失尚未提交的对局。
排行榜显示前 50 名，每用户一条最高分；所有难度共用排行，同分按注册顺序排列。

新功能需配套更新后端，并先手动执行后端仓库的 `sql/20260913_auth_snake.sql`。前端不创建数据库表。
会话依赖后端的 HttpOnly Cookie，前后端通过同源 `/api` 访问。生产 HTTPS 部署请在后端启用 `SESSION_COOKIE_SECURE=true`。

### 2048、推箱子与扫雷

三个游戏共用已有登录账号，但分别排行。新增接口需要手动执行后端仓库的 `sql/20260913_arcade_games.sql`，不会修改已有贪吃蛇成绩。

- `/#/games/2048`：标准 4×4 棋盘，同数合并计分，达到 2048 获胜；无路可走或主动结束时保存本局分数。按个人最高分排行。支持方向键、WASD、触屏滑动及间距 24px 的 60px 方向按钮。
- `/#/games/sokoban`：5 个独立关卡，将箱子全部推上目标后自动保存。每关按个人最少通关步数排行，失败或主动结束不入榜。卡住可重玩本关。
- `/#/games/mines`：初级 9×9 / 10 雷、中级 12×12 / 24 雷、高级 16×16 / 40 雷。首次翻格及其邻格安全，空白区自动展开；右键插旗，手机用模式按钮切换。每个难度按最快通关时间排行，失败不入榜。

扫雷时间由后端从创建对局到成功提交计算，含暂停、离开页面和网络传输时间；界面游戏中显示本地计时，保存后显示服务端成绩。
每人每榜只保留最佳成绩，同成绩按注册顺序排列。游客可试玩，登录后新开的对局才入榜。
三个游戏切换时各自保留进度并暂停；刷新页面或切换登录身份会重置未提交的对局。保存失败可重试，不会重复计分。
操作记录最多 20000 次，达到上限时自动结束；推箱子和扫雷仍需完成通关才能进入排行榜。

前后端分别维护相同的 `sokobanLevels.json` / `sokoban-levels.json` 关卡数据，更新关卡规则时必须同步发布。

## 账号管理

支持新增、编辑、删除确认、服务端搜索和环境筛选，以及提交状态和失败提示。
列表默认每页 10 条，可选择 5、10、50 条；切换筛选或条数回到第一页，删除末页最后一条后自动回到有效页。
顶部概览统计全部账号；编辑、删除分别请求 `PUT /api/accounts?id=10`、`DELETE /api/accounts?id=10`。
查询已改为分页对象，发布时需同时更新后端。
接口响应和联调规则见 [账号接口约定](docs/account-api-contract.md)。

## 开发工具

通过侧栏进入，也可直接打开 `/#/tools/json` 或 `/#/tools/diff`。两个工具不依赖后端，导入的文件和输入内容仅在浏览器本地处理，不发送到服务器或持久化保存；切换菜单时保留内容，刷新页面后清空。

- **JSON 格式化**：单个编辑框，点击格式化或压缩直接更新框内内容，语法错误时保留原文；支持导入 JSON/TXT 文件、2/4 空格缩进、复制和下载。保留长整数、数值原始写法和重复键。输入上限 200 万字符，格式化结果上限 400 万字符。
- **文本对比**：输入、粘贴或左右分别导入文件后自动对比（150ms 防抖），直接在两个编辑框中用红色标出差异，相同时不显示提醒。支持交换左右和忽略行首尾空白。统一处理不同系统的换行符，额外空行以红色换行符标记。两侧合计上限 40 万字符、6000 行。

文件需为 UTF-8 编码的纯文本（如 TXT、JSON、Markdown、CSV 或代码文件），不支持 Word/PDF 或二进制文件。导入失败不会覆盖当前内容。

处理在 Web Worker 中运行，耗时过长时提示分段处理。复制需要浏览器支持剪贴板权限；复制失败时可手动选择结果复制。

## 网速测试

入口 `/#/tools/speed`。使用 `@cloudflare/speedtest` 作为浏览器测量引擎，测速数据连接同域 `/speed/`，生产节点是用户位于北京的 DevHub 服务器，不再访问 Cloudflare 测速节点。

- 下载、上传仪表盘显示 Mbps / MB/s，保留延迟、抖动、延迟曲线与稳定性评级。
- 常用网站访问占据独立整行区域，每个网站有大号读数、颜色标签和刻度指针。本站参考分档：≤200ms 绿色，>200 且 ≤500ms 黄色，>500ms 红色。未测得、停止、测量中保持灰色；超过 1,000ms 指针到右端，数字保留实测值。
- 稳定性参考分档仍按抖动：≤10ms 绿色，>10 且 ≤30ms 黄色，>30ms 红色。测试结束且至少有 10 个有效延迟样本才评级。
- 常用网站在带宽测速前测量：直接加载抖音、百度、淘宝公开图标，每站 3 次取成功样本中位数，每次超时 4 秒。唯一查询参数避免浏览器缓存命中，不经后端代理。结果是资源加载耗时（可能来自 CDN），不等于 App 启动时间或 Ping；失败显示“未测得”。
- 单次计划有效载荷最多约 85MB（重试可能增加流量），单请求超时 15 秒，整体超时 90 秒。页面提示预计 30～60 秒；短时测试可能低估高速宽带，服务器带宽上限也会限制结果。
- 不自动测速；停止、离开工具页、页面隐藏或离线会取消请求。关闭测量库的日志上报，不启用 TURN 或丢包探测。

测速接口随前端镜像部署，无需修改 Java 后端：

- Nginx 将 `/speed/` 转发给容器内仅监听 `127.0.0.1:9020` 的 Node 服务。下载返回指定大小的二进制数据，上传完整读取后才应答，不写磁盘。
- 单请求最多 20,000,000 字节，关闭压缩、缓存及代理缓冲；每 IP 限制 3 个并发、每秒 20 次请求（突发 40 次）。接口只接受固定下载和上传路由。
- 生产容器的 Node 主进程管理 Nginx 生命周期。GitHub Actions 部署包包含服务文件，上线前构建并检查运行镜像。
- `npm run dev` 通过 Vite 中间件提供相同接口，页面明确显示“本地开发节点”。本地环回速度不能当成家庭宽带速度；实际网络测速请在部署后访问北京服务器的页面。

验证：`npm test`、`npm run build`。接口测试使用本机临时端口，检查下载字节数、上传完整接收、参数上限；另含分档边界、取消、超时与重测测试。
